Guide pratique

Installer et utiliser Flux Studio

Suivez ces étapes pour relier le studio web local au serveur ComfyUI. Les commandes ci-dessous sont prévues pour Windows PowerShell.

1. Comprendre les composants

Interface

Application web monopage en JavaScript ES modules, sans framework. Elle contient les vues App, Workflow, Gallery, Models, Prompts, Canvas, ComfyUI et Matériel.

Serveur Flux Studio

Serveur Python standard-library sur le port 8080. Il sert l’interface et expose l’API locale, SQLite, les téléchargements et les intégrations.

ComfyUI

Moteur de génération indépendant, habituellement sur 127.0.0.1:8188. Les graphes Flux Studio sont traduits et soumis à son endpoint /prompt.

Données locales

SQLite pour le catalogue d’images et modèles, IndexedDB dans le navigateur pour workflows/préférences, et fichiers JSON pour la configuration et l’index LoRA.

Flux Studio s’inscrit aussi dans une démarche d’apprentissage de l’IA appliquée au soutien informatique : explorer des intégrations solides et mieux comprendre les connexions entre outils. Les sujets comme les connecteurs, les protocoles d’outils (dont MCP) et leur orchestration en équipe restent des pistes d’exploration, et non des fonctions annoncées dans l’application.

2. Installer et configurer

  1. Installez Python 3.11 ou une version ultérieure et ComfyUI sur l’ordinateur qui exécutera les générations.
  2. Clonez le dépôt Flux Studio et placez-vous dans le dossier du projet.
git clone https://github.com/youneselfakir0/flux-studio.git
cd flux-studio
  1. Copiez .env.example vers .env. Adaptez COMFYUI_ROOT si ComfyUI n’est pas dans le chemin par défaut. Les clés d’intégration sont optionnelles; gardez-les uniquement dans le fichier local .env.
  2. Démarrez ComfyUI en local. Le chemin Python de l’environnement virtuel dépend de votre installation.
cd C:\chemin\vers\ComfyUI
.\.venv\Scripts\python.exe main.py --listen 127.0.0.1 --port 8188
  1. Dans un second terminal, depuis la racine Flux Studio, lancez le backend.
python app\server.py
  1. Ouvrez http://127.0.0.1:8080. Vérifiez que les modèles attendus sont installés et chargés dans ComfyUI.

Par défaut, le serveur est lié à localhost. Ne remplacez pas cette adresse par une écoute publique sans architecture de sécurité dédiée : l’application n’a pas de système d’authentification.

3. Faire une première génération (mode App)

  1. Ouvrez l’onglet App, puis sélectionnez un modèle disponible sur votre installation.
  2. Renseignez un prompt positif et, si le modèle l’utilise, un prompt négatif.
  3. Choisissez largeur, hauteur, nombre d’étapes, CFG, seed et LoRA. Un seed vide est généré aléatoirement.
  4. Cliquez Générer. L’interface construit le workflow correspondant et l’envoie à ComfyUI.
  5. Consultez le résultat dans la carte qui apparaît sous les paramètres. Les tâches et erreurs ComfyUI sont consultables depuis Gallery.

4. Construire un workflow nodal

  1. Ouvrez l’onglet Workflow. La colonne gauche contient les workflows prêts, les mots-clés LoRA et le catalogue de nœuds.
  2. Choisissez un workflow prêt à l’emploi ou faites glisser les nœuds sur le canevas.
  3. Reliez les ports compatibles, puis sélectionnez un nœud pour modifier ses champs dans l’inspecteur.
  4. Utilisez Ctrl+K pour rechercher une LoRA, Ctrl+Z pour annuler et Ctrl+S pour enregistrer.
  5. Utilisez Valider le workflow pour vérifier sa compatibilité ComfyUI; lancez-le ensuite avec Run ou Ctrl+Entrée.

La validation distante envoie un prompt de test à ComfyUI puis tente de le retirer de la file. Elle n’interrompt pas volontairement les autres tâches; si le nettoyage n’est pas confirmé, l’interface l’indique.

5. Découvrir les autres vues

  • Gallery : parcourir les images/prompt présents dans la base et suivre les générations.
  • Models : inspecter les modèles ComfyUI et, si Civitai est configuré, rechercher et télécharger des fichiers.
  • Prompts : filtrer les exemples importés depuis le catalogue SQLite.
  • Canvas : ouvrir l’éditeur d’image intégré.
  • ComfyUI et Matériel : vérifier les modèles installés, les téléchargements et les informations locales.
  • Outils : accéder à la prévalidation, au préchargement, aux prompts récents, aux suggestions LoRA et à la libération de mémoire.

6. Lancer les tests sans GPU

Les tests automatisés couvrent l’API, SQLite, la configuration, les intégrations mockées et la sérialisation de graphes. Ils n’exécutent pas de génération GPU.

python -m unittest discover -s tests -v
node --test tests_js\graph.test.mjs
python -m compileall -q app tests

7. Diagnostiquer les problèmes usuels

ComfyUI indisponible

Vérifiez que ComfyUI tourne sur l’URL configurée et testez http://127.0.0.1:8188/object_info. Le serveur Flux Studio doit rester actif séparément.

Modèle absent ou valeur refusée

Installez le modèle requis et rescanez. Les menus sont renseignés par ComfyUI; les noms des modèles doivent correspondre exactement.

Génération en erreur

Ouvrez le détail d’exécution et vérifiez le nœud/champ refusé, le modèle sélectionné, la VRAM disponible et les logs ComfyUI.

Fonction Civitai/vision désactivée

Ajoutez le token Civitai ou la clé Gemini au fichier .env local si nécessaire, puis redémarrez le backend. Ne publiez jamais ces secrets.

Hébergement du backend : prérequis

La page GitHub Pages est un site de documentation statique. Pour utiliser Flux Studio à distance, votre serveur doit aussi héberger le backend, ComfyUI, les modèles, la base et les données persistantes. L’application actuelle est mono-utilisateur locale, sans authentification; l’exposer directement sur Internet n’est pas sûr. Il faut d’abord préciser le système d’exploitation et l’accès réseau du serveur, puis choisir une protection (au minimum TLS, authentification devant l’application et pare-feu/VPN) et configurer le stockage GPU de façon durable.

Ne mettez pas .env, les tokens API, la base SQLite personnelle, l’index privé ou les modèles dans le site public GitHub Pages.
